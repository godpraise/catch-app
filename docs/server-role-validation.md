# 역할·사진 권한 후속 검증 — 2026-11-16

Codex의 도움으로 구현·테스트한 로컬 미배포 변경이다. 사용자가 과거 직접 작성한 코드라는 의미가 아니다. 원본·기존 배포 상태와 구분한다.

## 변경

- 대기 방은 초대 코드로 조회할 수 있고 전체 방 목록은 공개하지 않는다. 진행 중인 방은 참가자에게만 읽기를 허용한다.
- 방 생성과 방장 참가자 생성, 시작 시 회차 증가와 전체 역할 배정을 원자적으로 저장한다.
- 방장만 시작·역할 초기화를 수행한다. 현재 회차의 술래만 살아 있는 도망자를 탈락 처리한다. 갱신 필드와 `caughtBy`를 검사한다.
- 본인 위치·미션만 허용된 상태·필드로 갱신한다. 이전 회차 요청과 다른 사람 정보의 변조를 거부한다.
- 사진은 `rooms/{code}/{uid}/{fileName}`에 저장한다. 현재 살아 있는 참가자의 본인 경로에 10MiB 미만 JPEG 생성만 허용하고 덮어쓰기를 거부한다. 방 참가자의 SDK 읽기만 허용한다.
- 앱 진입점 `App.js` → `src/navigation/AppNavigator.js` → `src/screens`에서 사용하는 `src/firebase/rooms.js`를 수정했다. 2026-11-20에는 참조되지 않는 구형 중복 파일과 미사용 화면·중복 설정을 정리했다. 이전 파일은 Git 이력에 남아 있다.

## 재현

Node와 Java 21 이상이 설치된 환경에서 다음을 실행한다.

```sh
cd security
npm ci
npm test
```

`demo-catch-role-validation`, localhost Firestore 8787·Storage 9199에서 실행한다. 운영 설정·운영 데이터·카카오 서버는 사용하지 않는다. 테스트 의존성은 Firebase SDK 13.3.0, 실제 보존 앱 의존성은 10.12 계열이므로 네이티브 앱 전체 빌드 검증과 구분한다.

17개 모두 통과: 비로그인·외부 읽기, 초대 코드 조회, 원자적 생성, 본인 참가, 늦은 참가·덮어쓰기 거부, 방장 시작·역할 변경 제한, 원자적 회차 초기화, 불일치 초기화 거부, 술래 포획, 위조 포획·필드 거부, 본인 위치, 본인 미션, 종료·나가기, 오래된 회차 거부, 사진 생성·읽기, 사진 형식·크기·덮어쓰기·구형 경로 거부, 실제 앱 방 서비스의 생성→참가→시작→사진→포획→종료→재시작.

## 남은 범위

- Expo/EAS 전체 빌드, 실제 카카오 로그인·기기 카메라·GPS·다중 기기는 시험하지 않았다.
- 역할 검증은 Firebase 서버의 규칙 엔진이 담당하지만 승패·미션·위치의 진실성까지 서버가 판정하는 구조는 아니다. GPS 위조·랜덤 배정의 공정성·방장 이탈·시작과 참가의 경쟁·서버 기준 인원 제한은 별도 과제다.
- `users`의 통계는 본인 갱신 값이다. 서버가 보증하는 공식 순위가 아니다.
- 이미 발급된 다운로드 토큰 URL은 공유 시 소지자가 접근할 수 있다. SDK 읽기 규칙 강화가 기존 토큰 URL을 무효화하지 않는다.
- 구형 사진 경로는 새 규칙에서 거부한다. 기존 파일은 삭제하지 않았으며 호환성과 보관 정책을 배포 전에 결정한다.
- 앱 코드와 규칙을 함께 전환하고, 실제 환경에서 확인해야 한다. 2026-11-16 구현 당시에는 배포하거나 GitHub에 푸시하지 않았다. 2026-11-20에는 소스와 설명을 GitHub에 반영하며, 운영 서비스는 미배포 상태로 유지한다.
