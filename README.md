# 찍히면 아웃 (Catch App)

친구들이 오프라인 술래잡기에 함께 참가하고, 촬영 후 대상을 선택·확정해 탈락 상태를 공유하는 모바일 앱입니다. 사진만으로 사람을 자동 인식하는 기능은 아닙니다.

## 작업 범위

- 개발 기간: 2025.11~2026.01 (기존 이력서와 사용자 회고 기준)
- 지인이 제안한 아이디어를 상세 기획과 UX 흐름으로 구체화했습니다.
- AI 도구를 활용해 구현하고, 인증·권한·빌드 오류를 검토·수정하고 배포했습니다.
- 팀 프로젝트가 아닌 개인 제작 프로젝트입니다. 도구의 도움과 본인의 판단을 구분합니다.
- 사용자 확인: 직접 코드를 편집하기보다 문제를 설명해 AI에 수정을 요청하고 실행 결과를 확인했습니다. 독립 작성 코드의 비율을 주장하지 않습니다.

## 기술과 구조

React Native, Expo, Firebase Authentication, Firestore, Storage, Cloud Functions, Kakao 로그인, EAS Build를 사용합니다.

`App.js`는 진입점, `src/screens/`는 화면, `src/firebase/`는 인증·방·게임 상태 처리, `functions/index.js`는 카카오 토큰을 검증해 Firebase Custom Token을 발급하는 서버 함수입니다. 방·참가자 문서를 실시간으로 구독합니다.

## 실행 준비

이 저장소는 원본 보존본에서 인증·서명 자료와 실제 서비스 설정값을 분리한 등록용 복사본입니다. 자신의 Firebase·Kakao·Expo 프로젝트 설정이 필요합니다.

1. `npm ci`로 앱 의존성을 설치합니다. 의존성 버전은 당시 보존본의 `package.json`과 lock 파일을 유지했습니다.
2. `src/firebase/config.js`의 `YOUR_FIREBASE_*` 값을 자신의 Firebase 웹 앱 설정으로 채웁니다.
3. `app.json`의 Kakao 네이티브 앱 키와 Expo/EAS 프로젝트 ID, `.firebaserc`의 Firebase 프로젝트를 자신의 것으로 설정합니다. `functions/app.json`에도 별도의 Expo 프로젝트 설정이 남아 있으므로 사용 여부에 맞춰 설정합니다.
4. 서버 함수를 사용하려면 `functions/`에서 `npm ci` 후 자신의 Firebase 환경에 배포하고, `src/firebase/auth.js`의 `EXCHANGE_TOKEN_URL`을 그 함수 URL로 바꿉니다. 기존 운영 서비스에 자동으로 배포하지 않습니다.
5. `npx expo start --dev-client`로 시작합니다. 네이티브 Kakao 로그인은 Expo Go 대신 별도의 개발 빌드와 플랫폼 등록이 필요합니다.

## 확인 수준과 남은 과제

사용자는 보존된 소스가 마지막 배포에 사용한 버전이라고 확인했습니다. 이 등록용 복사본은 설정값을 익명화했으므로 그대로 배포한 파일과 바이트가 같지는 않습니다. 등록 작업에서 앱 전체를 재빌드하거나 운영 서버·실기기 플레이를 검증한 것은 아닙니다.

지인과 동생의 시연 반응 및 미션 등 콘텐츠 추가 의견은 사용자 회고입니다. 실제 이용자 수·재사용률·매출 자료는 없습니다. 함수 단위 모의 환경에서 3인 역할 배정과 선택한 참가자의 탈락을 확인한 기록은 실기기 통합 검증과 구분합니다.

2026-11-16 후속 개선에서 Firestore 규칙이 방장·술래·본인과 현재 회차별 쓰기를 제한하도록 수정했습니다. Storage 규칙에 참가자 읽기, 본인 경로의 JPEG·크기 제한과 덮어쓰기 거부를 추가했습니다. 실제 앱의 방 서비스 함수 흐름을 포함해 로컬 에뮬레이터 17개 테스트를 통과했습니다. **AI 도구를 활용한 이번 개선은 미배포이며, 실기기·운영 인증·전체 게임 공정성을 검증한 것은 아닙니다.** 재현 방법과 한계는 [권한 검증](docs/server-role-validation.md)에 정리했습니다.

## 보존과 권리

기존 Git 이력, 설치 라이브러리, 서명용 키, 로컬 설정은 복사하지 않았습니다. 원본은 별도로 보존되어 있습니다. 새 오픈소스 라이선스를 임의로 추가하지 않았습니다.
