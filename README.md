# 찍히면 아웃 (Catch App)

친구들이 오프라인 술래잡기에 함께 참가하고 게임 상태를 공유하는 모바일 앱입니다. 사진을 촬영한 뒤 대상을 직접 선택·확정해 탈락 처리합니다. 사진 속 사람을 자동 인식하는 기능은 아닙니다.

React Native·Expo·Firebase·Kakao 로그인·EAS Build를 사용했습니다. 기본 앱은 2025년 11월~2026년 1월에 개발·배포했습니다. 이 저장소에는 이후 로컬에서 보완한 역할·회차·사진 접근 규칙도 포함합니다. **후속 개선은 실기기·운영 환경에 미적용 상태입니다.**

## 맡은 역할과 AI 활용

지인의 아이디어를 화면과 게임 흐름으로 상세 기획하고 AI 도구로 구현했습니다. 인증·빌드·권한 오류는 상황을 설명해 수정을 요청하고 실행 결과를 확인했습니다. 전체 코드를 직접 독립 작성한 프로젝트로 설명하지 않습니다.

지인·동생과 테스트할 때 콘텐츠 추가 요청을 받아 GPS 거리·온도 힌트를 반영했습니다. 재미·이용 시간의 변화나 재참여율은 측정하지 않았습니다.

## 게임 흐름과 코드 구조

로그인 후 방을 만들거나 초대 코드로 참가합니다. 방장이 시작하면 역할을 배정받고 숨기·플레이를 진행합니다. 술래는 촬영·대상 선택·탈락 확정을 거쳐 결과를 공유합니다.

```text
App.js                       앱 진입점
src/navigation/              화면 경로 등록
src/screens/                 로그인·방 참가·역할·촬영·결과 화면
src/firebase/                인증·게임방·상태·사진 서비스
src/components/              공통 화면 요소
src/theme/                   색상·간격·글자 스타일
src/utils/                   거리 계산 등
functions/index.js           Kakao 토큰 확인·Firebase Custom Token 발급
firestore.rules              역할·회차별 데이터 접근 규칙
storage.rules                사진 경로·유형·크기·접근 규칙
security/                    로컬 에뮬레이터 테스트
```

Firestore 실시간 구독으로 방·참가자 상태를 공유하고 사진은 Firebase Storage에 저장합니다. [파일 정리 내역](docs/code-structure.md)

## 권한 문제와 후속 개선

로그인 여부만으로는 다른 참가자의 정보를 변경하는 요청을 충분히 제한할 수 없어 역할과 현재 회차를 함께 검증하도록 보완했습니다.

- 방장만 게임 시작·역할 배정을 수행합니다.
- 현재 회차의 술래만 살아 있는 도망자를 탈락 처리합니다.
- 일반 참가자는 허용된 본인 위치·미션 정보만 수정합니다.
- 사진은 참가자의 본인 UID 경로에 JPEG·크기 제한을 적용하고 덮어쓰기·외부 접근을 제한합니다.

AI 도구를 활용한 구현 범위, 테스트 조건과 제한은 [권한 검증 문서](docs/server-role-validation.md)에 정리했습니다.

## 실행 준비

인증·서명 자료와 서비스 설정을 분리한 검토용 소스입니다. 자신의 Firebase·Kakao·Expo 프로젝트 설정이 필요합니다.

1. 루트에서 `npm ci`로 앱 의존성을 설치합니다.
2. `src/firebase/config.js`의 `YOUR_FIREBASE_*`를 자신의 설정으로 채웁니다.
3. 루트 `app.json`의 Kakao 키·Expo/EAS 프로젝트 ID와 `.firebaserc`를 자신의 프로젝트로 설정합니다.
4. 서버 함수를 사용하려면 `functions/`에서 `npm ci` 후 자신의 환경을 설정합니다. `src/firebase/auth.js`의 `EXCHANGE_TOKEN_URL`도 자신의 함수 주소로 변경해야 합니다.
5. `npx expo start --dev-client`로 실행합니다. 네이티브 Kakao 로그인은 Expo Go 대신 개발 빌드와 플랫폼 등록이 필요합니다.

서비스 배포 명령은 위 실행·검증 과정에 포함하지 않습니다.

서버 함수 문법은 루트에서 `npm --prefix functions run check`로 확인할 수 있습니다. Firebase 배포 전 검사도 이 명령에 연결했습니다. 실제 배포·운영 검증을 대신하지는 않습니다.

## 로컬 테스트

테스트에는 Node.js 22 이상과 Java 21 이상을 권장합니다.

```sh
cd security
npm ci
npm test
```

`demo-catch-role-validation`과 로컬 Firestore·Storage 에뮬레이터를 사용합니다. 역할·회차·사진 규칙과 실제 방 서비스의 생성·참가·시작·사진·탈락·종료·재시작 흐름에 관한 17개 시나리오를 검증합니다. 테스트 SDK와 기존 앱 SDK의 버전은 다르므로 앱 전체 빌드·실기기 검증과 구분합니다.

[2026-11-20 재검증](docs/verification-2026-11-20.md)에서 17개 모두 통과했습니다.

## 확인한 결과와 남은 검증

로컬 테스트는 운영 인증·실제 카메라·GPS·다중 기기 플레이를 검증한 결과가 아닙니다. 후속 개선은 미배포이며 실제 이용자 수·완주율·재참여율·매출 자료도 없습니다.

GPS 위조, 서버 기준 승패·통계, 방장 이탈, 인원 제한, 동시 참가·시작, 다운로드 토큰 URL 공유는 별도 과제입니다. 역할 규칙을 보완한 것만으로 게임 공정성 전체를 해결했다고 주장하지 않습니다.

원본·기존 Git 이력은 보존합니다. 설정값을 분리한 소스이므로 최초 배포 파일과 바이트 단위로 같지는 않습니다. 새 오픈소스 라이선스를 임의로 부여하지 않았습니다.
